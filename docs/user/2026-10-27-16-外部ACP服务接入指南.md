# 外部 ACP Server 接入指南

> 面向：要实现或接入外部 Agent 的开发者
> 目标：让 Gateway 能通过 WebSocket 调用你的 ACP Server

## 1. 整体模型

```text
客户端
  │ CAP
  ▼
AgentGateway
  │ ACP JSON-RPC over WebSocket
  ▼
你的 ACP Server
  │
  └── 自己的模型 / 工具 / 进程
```

对 Gateway 来说，你的服务就是 **ACP Agent**：

- Gateway 是 ACP Client；
- 你的服务是 ACP Server；
- Gateway 只负责连接和转发，不负责启动你的 Agent。

## 2. 最小协议契约

你的服务只需要暴露一个 WebSocket 地址，例如：

```text
wss://agent.example.com/acp
```

规则：

1. 每个 WebSocket **text frame** 放一条 JSON-RPC 2.0 消息；
2. 请求必须原样回传 `id`；
3. 通知不带 `id`；
4. 一个 WS 连接内先 `initialize`，再 `session/new`，再 `session/prompt`；
5. 流式内容用 `session/update` 通知推给 Gateway。

### 必须处理的方法

| 方法 | 作用 |
|---|---|
| `initialize` | 协商协议版本和能力 |
| `session/new` | 创建会话，返回 `sessionId` |
| `session/prompt` | 执行一轮输入，返回 `stopReason` |

### 建议处理

| 方法 | 作用 |
|---|---|
| `session/cancel` | 取消当前轮 |
| `session/request_permission` | 请求用户确认敏感操作 |
| `fs/*` | 文件读写（可选） |

### 流式通知

```json
{
  "jsonrpc": "2.0",
  "method": "session/update",
  "params": {
    "sessionId": "sess-1",
    "update": {
      "sessionUpdate": "agent_message_chunk",
      "content": { "type": "text", "text": "你" }
    }
  }
}
```

常用 `sessionUpdate`：

- `agent_message_chunk`：正文增量；
- `agent_thought_chunk`：思考过程；
- `tool_call` / `tool_call_update`：工具状态；
- `usage_update`：token/费用（可选）。

## 3. 两种实现方式

### 方式 A：你的服务原生支持 ACP over WS

直接实现上面的方法即可，不需要额外适配层。

### 方式 B：你只有 stdio ACP Agent

做一个 WS ↔ stdio 代理：

```text
Gateway --WS--> 你的服务 --stdio--> 本地 Agent
```

把 WS 帧写入 Agent 的 stdin，把 Agent stdout 的 JSON-RPC 行发回 WS。

> 参考实现：`AcpAgentServer` 模块，它把 `qwen --acp` 包装成 WS ACP Server。

## 4. 注册到 Gateway

外部 Agent 只注册 **wsUrl**，不要注册 command/args。

```http
POST http://localhost:8080/admin/agents
Content-Type: application/json

{
  "agentId": "my-agent",
  "wsUrl": "wss://agent.example.com/acp",
  "authToken": "optional-bearer-token",
  "mcpUrl": "https://gateway.example.com/mcp"
}
```

字段说明：

| 字段 | 必填 | 说明 |
|---|---|---|
| `agentId` | 是 | 全局唯一名称 |
| `wsUrl` | 是 | Gateway 能访问到的 ACP WS 地址 |
| `authToken` | 否 | 以 `Authorization: Bearer` 发送 |
| `mcpUrl` | 否 | 你的 Agent 可访问的 Gateway MCP 地址 |



## 5. 验证

1. 启动你的 ACP Server；
2. 注册到 Gateway；
3. 查询：

```http
GET /agents
```

应能看到：

```json
{
  "name": "my-agent",
  "available": true
}
```

4. 调用：

```http
POST /chat
{
  "v": "0.1",
  "id": "1",
  "type": "chat",
  "payload": {
    "clientId": "agent-client",
    "prompt": "你好",
    "agent": "my-agent"
  }
}
```

5. 确认返回 `final`，并观察 `session/update` 是否按增量到达。

## 6. 关键注意

- **wsUrl 必须是 Gateway 能访问的地址**：同机可用 `localhost`，跨机器必须用真实域名/IP。
- **一个 WS 连接对应一个会话/Agent 实例**：demo 可以简单处理，生产要考虑连接池/多路复用。
- **管理接口目前没有鉴权**：只用于本地 demo，生产必须加管理员鉴权。
- **TLS**：公网使用 `wss://`，并校验证书。
