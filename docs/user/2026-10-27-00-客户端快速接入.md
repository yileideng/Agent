# 客户端快速接入

> 读者：外部客户端开发者
> 目标：跑通“注册工具 → 工具调用 → 对话”最小链路
> 详细协议：[2026-10-27-00-客户端接入指南.md](./2026-10-27-00-客户端接入指南.md)

## 1. 注册客户端和工具

```http
POST /clients/register
Content-Type: application/json
```

```json
{
  "v": "0.1",
  "id": "reg-1",
  "type": "register_tools",
  "payload": {
    "clientId": "xiaohongshu",
    "clientType": "SERVER",
    "baseCallbackUrl": "https://client.example.com",
    "defaultCallbackPath": "/client/tools/execute",
    "tools": [
      {
        "name": "get_user_profile",
        "description": "获取当前用户资料",
        "inputSchema": {
          "type": "object",
          "properties": {},
          "additionalProperties": false
        }
      }
    ]
  }
}
```

- `clientType=SERVER`：工具走 HTTP 回调，`baseCallbackUrl` 必填，且它是**客户端自己的**回调地址，不是网关地址；
- `clientType=MOBILE`：工具走 WebSocket，不需要回调地址；
- WS 客户端也先走这个 HTTP 注册接口，WS 只负责工具调用；
- `inputSchema` 是标准 JSON Schema，必须写清参数；
- 同一 `clientId` 重复注册会**全量替换**工具目录。

注册成功返回 `tools_ack`，`payload.registered` 是本次注册的工具数量。

## 2. 执行工具

### SERVER：提供 HTTP 回调

网关会向 `baseCallbackUrl + callbackPath` POST：

```json
{
  "v": "0.1",
  "type": "tool_call",
  "payload": {
    "chatId": "chat-1",
    "callId": "call-1",
    "tool": "get_user_profile",
    "arguments": {},
    "deadlineMs": 30000
  }
}
```

客户端执行后原样返回：

```json
{
  "v": "0.1",
  "type": "tool_result",
  "payload": {
    "callId": "call-1",
    "status": "success",
    "result": { "name": "张三" }
  }
}
```

失败时用 `"status":"error"`，并带 `error.message`。

### MOBILE：连接 WebSocket

```text
ws://<AgentAdaptor>/ws/agent
```

`<AgentAdaptor>` 是网关地址，例如 `localhost:8080`；不是客户端自己的地址。

1. 连接后发 `hello`，带 `clientId`、`endUserId`；
2. 收到 `tool_call` 后执行；
3. 在同一条连接回 `tool_result`。

## 3. 发起对话

```http
POST /chat
Content-Type: application/json
Accept: application/json
```

```json
{
  "v": "0.1",
  "id": "req-1",
  "type": "chat",
  "payload": {
    "clientId": "xiaohongshu",
    "endUserId": "u-123",
    "prompt": "帮我写一篇咖啡测评"
  }
}
```

默认返回 `final`，payload 含 `sessionId / chatId / agent / output`；`sessionId` 用于下一轮续聊。

### 流式

把 `Accept` 改为 `text/event-stream`，会收到：

- `delta`：文本增量；
- `thinking`：思考增量（可能没有）；
- `final`：完整结果；
- `error`：失败。

工具调用仍然走 HTTP 回调或 WebSocket，不在聊天流里。

## 4. 最小验收

- `GET /clients` 能看到 `clientId` 和工具；
- `POST /mcp/{clientId}` 的 `tools/list` 能返回工具；
- 对话中能收到 `tool_call` 并回 `tool_result`；
- `POST /chat` 能返回 `final`，或 `Accept: text/event-stream` 能收到 `delta/final`。

## 5. 常见问题

| 现象 | 排查 |
|---|---|
| 注册 400 | 检查 `clientId`、`clientType`、`tools[].inputSchema` |
| Agent 看不到工具 | 检查 `tools/list` 和注册是否成功 |
| 收不到 `tool_call` | SERVER 检查回调地址/公网可达；MOBILE 检查 WS 是否 `hello` |
| 工具超时 | 检查 `deadlineMs` 内是否回 `tool_result` |
| 没有流式效果 | 检查 `Accept` 和 Agent 是否支持流式 |

完整字段、错误码和 SDK 用法见 [2026-10-27-00-客户端接入指南.md](./2026-10-27-00-客户端接入指南.md)。
