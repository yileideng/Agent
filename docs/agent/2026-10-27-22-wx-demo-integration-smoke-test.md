# wxDemo × AgentGateway 交互冒烟测试

> 用途：一次性验证客户端与网关之间的完整交互链路
> 前提：网关已启动（默认 `http://127.0.0.1:8080`），wxDemo 已启动且状态显示「已就绪」

## 0. 准备

1. **清空画布**：`Ctrl+R`（重置画布），确保从空画布开始，坐标不会和旧图元撞上。
2. 确认面板右上角是绿色「已就绪」。
3. 打开网关控制台，后面要对照 `[HTTP]` 日志。

## 1. 全链路自检（主提示词，单轮）

直接复制进输入框：

```text
先读一遍当前画布，然后按顺序做这几件事，中间不要停下来问我：
1. 在坐标 (200, 300) 放一个与门；
2. 在 (60, 260) 和 (60, 340) 各放一个输出引脚（方形，它是信号源）；
3. 把这两个输出引脚分别连到与门的 in0 和 in1；
4. 在 (290, 300) 放一个输入引脚（圆形，它是接收端），把它连到与门的 out；
5. 把 (60, 260) 那个输出引脚设为 High，另一个设为 Low；
6. 再读一次画布，告诉我输入引脚现在是什么电平、与门输出是什么，以及一共形成了几个网络。

某一步失败就说明原因后继续做下一步，不要重复已经成功的步骤。
```

> **方向别写反**：`SourcePin`（方形）是信号源，`SinkPin`（圆形）是接收端。
> 让 `SinkPin` 当源是连不通的——它只进「汇表」，没有输出端点。

### 这一条覆盖了什么

| 交互点 | 触发方式 | 怎么确认 |
| --- | --- | --- |
| 工具注册 / MCP 暴露 | 客户端启动时已完成 | 网关日志 `[ClientRegistry] 客户端 ... 注册工具` |
| `get_circuit` 只读工具 | 第 1 步、第 6 步 | 日志 `[AgentToolServer] tool=get_circuit` |
| `add_component` 写工具 | 第 1、2、4 步 ×4 | 画布出现 1 个与门 + 2 个方引脚 + 1 个圆引脚 |
| `connect_pins` 连线 | 第 3、4 步 ×3 | 画布出现三条线，线头落在红点上 |
| `set_output_pin` 改电平 | 第 5 步 ×2 | 方引脚文字变化，与门输出重算 |
| 写操作回读校验 | 每次写操作返回 | `verified.ok` / `verified.connected` 为 true |
| **SSE 流式** | 整轮回答较长 | 文字分段出现，不是最后一次性刷出 |
| **HTTP 回调链路** | 所有工具 | 日志 `[HTTP] 收到 POST /client/tools/execute` |
| **Markdown 渲染** | 回答含列表 | 面板显示为列表，不出现 `**` 或 `-` 原字符 |
| **工具调用反馈** | 调工具期间 | 状态行显示「思考中…」 |

### 预期结果

回答里应该能说出：

- 与门的输出电平（High AND Low = **`Low`**）；
- 输入引脚（圆形）的电平应该也是 `Low` —— 它和与门输出在同一个网络；
- **网络数量**：两个源各接一个门输入 → 2 个网络；门输出接接收端 → 再加 1 个，共 **3 个**。

关键判定：**输入引脚（圆形）的电平必须和与门输出一致**。
如果它一直是 `Off`，说明值没有从门输出沿导线传到接收端。

## 2. 多轮续聊（验证 sessionId）

紧接着上一条，再发：

```text
刚才那个与门，如果把另一个输入也改成 High，输出会变吗？先别改，只回答。
```

**判定**：

- ✅ 它知道「刚才那个与门」指的是 `AndGate-1`，不需要你解释；
- ✅ 网关日志里这轮 `[HTTP] 入参` 的 `payload` 中出现 `"sessionId": "wx-demo:demo-user:..."`；
- ❌ 如果它反问「你指的是哪个电路」，说明 `sessionId` 没回传。

## 3. 图元角色识别（验证 role 没有被误解）

```text
这个画布上有没有不是电路元件的东西？有的话指出来，并说明你是怎么判断的。
```

**判定**：

- 如果画布上有矩形/圆/点，它应该说明这些是 `role=drawing` 的绘图元素，不是元件；
- ❌ 如果把矩形说成「导线」「边框元件」，说明提示词或返回结构没起作用。

## 4. 会话管理（界面操作，不靠提示词）

| 操作 | 预期 |
| --- | --- |
| 点「新对话」 | 输出区清空，状态回到「已就绪」 |
| 然后再发任意问题 | 网关日志里这轮入参**没有** `sessionId`（新会话） |
| 再追问「刚才问了什么」 | 它**答不上来**——这是正确的，说明新会话确实生效了 |

## 5. 连接自愈（验证 1.3 注册重试）

1. 关掉网关；
2. 关掉 wxDemo，重新打开 wxDemo；
3. 观察状态：应该是橙色「注册失败，重试中 (n/4)」；
4. 过一会儿再启动网关；
5. 观察状态：应在一次重试后自动变成绿色「已就绪」，**不需要重启客户端**。

补充验证：点「重连」按钮，状态应立刻变成「正在注册…」再回到「已就绪」。

## 6. 错误路径

| 场景 | 预期提示 |
| --- | --- |
| 未连接时点发送 | 「还没连上网关，稍等注册完成或点「重连」」 |
| 网关中途挂掉后提问 | 「请求失败」+ 具体原因，不应白等或崩溃 |
| 端口 18080 被占用 | 启动即提示「本地工具服务（127.0.0.1:18080）启动失败」 |
| 让 Agent 连一个不存在的引脚 | 工具返回错误，Agent 如实说明，不编造成功 |

## 7. 判定总表

| # | 检查项 | 通过标准 |
| --- | --- | --- |
| 1 | 注册 | 日志有 `注册工具`，面板绿色「已就绪」 |
| 2 | 只读工具 | 日志有 `tool=get_circuit` |
| 3 | 写工具 | 画布真的变化（肉眼可见） |
| 4 | 连线绑定 | `connect_pins` 返回 `verified.connected=true`，且线头落在红点上 |
| 5 | 电平重算 | 改**输出引脚**后，与门输出跟着变 |
| 6 | 流式 | 回答分段出现 |
| 7 | 续聊 | 第二轮入参含 `sessionId`，且能接上文 |
| 8 | 新对话 | 入参无 `sessionId`，且失忆 |
| 9 | 自愈 | 网关后启动，客户端自动连上 |
| 10 | 角色识别 | 不把 `drawing` 当电路元件 |
| 11 | 错误处理 | 四种错误场景都有明确文案 |
| 12 | 信号方向 | 输入引脚（圆）能显示门输出传过来的电平 |

## 8. 常见失败与定位

| 现象 | 先查什么 |
| --- | --- |
| Agent 完全看不到工具 | 网关日志 `GET /mcp/{clientId}` 的 `tools/list`；客户端是否注册成功 |
| 工具被调用但画布没变 | 坐标是否超出 `canvas` 范围（会返回错误而不是静默成功） |
| 连线了但电路不算 | `verified.connected` 是否为 false；是否把 `SinkPin` 当成了信号源 |
| 改电平后输出不变 | 改的是不是 `SinkPin`（它不能设值）；门输入是否真的更新了 |
| 第二轮失忆 | 入参 `sessionId` 是否为空 |
| 中文乱码 | 源文件是否为 UTF-8；界面文案是否用了 `wxT()` |

## 9. 提示词为什么这么写

几个刻意的设计，改提示词时留意：

- **给了绝对坐标**：避免模型自己算位置导致元件重叠、引脚坐标对不上，让连线失败；
- **坐标都在 300 以内**：画布宽度可能只有 314px（被左侧树和 AI 面板挤压），超了会报错；
- **明确「不要停下来问我」**：默认情况下模型会每一步征求确认，那样一次只验证一个点，很慢；
- **用 SourcePin 当源、SinkPin 当汇**：方向反了信号传不进去，这是最常见的错觉；
- **要求最后回读**：只有让它复述最终状态，才能验证「写操作真的生效」而不是「它以为生效了」；
- **步骤数控制在 9 次工具调用以内**：写操作有 20 次上限，但单轮步数太多容易在中途断掉；
- **第 5 步两个源都要设**：只设一个的话，另一个还是 `Off`，与门输出不确定，不好判定。
