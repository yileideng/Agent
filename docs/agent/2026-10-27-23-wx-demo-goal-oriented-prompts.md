# wxDemo 目标导向提示词集

> 用途：验证 Agent 能不能**自己规划**完成任务，而不是照着步骤清单执行
> 区别：链路冒烟测试见 [wxDemo 交互冒烟测试](./2026-10-27-22-wx-demo-integration-smoke-test.md)——那份给全步骤，只验通路

## 0. 为什么要换

原来的提示词是这样：

```text
1. 在坐标 (520, 300) 放一个与门；
2. 在 (320, 260) 和 (320, 340) 各放一个输出引脚；
3. 把这两个输出引脚分别连到与门的 in0 和 in1；
...
```

每个元件的类型、坐标、连线对象、设置顺序全给定了，模型只需要机械调用工具。
这测不出真实场景的能力——真实用户只会说「帮我搭个与门电路」。

下面四条按**开放度递增**排列，建议按顺序跑。

## 1. L1：目标明确，步骤自定

```text
在画布上搭一个两输入的与门电路：用两个输出引脚当信号源，接到与门的两个输入上，
一个设成高电平、另一个设成低电平。搭好之后告诉我与门的输出是什么。
```

**考察**：

| 点 | 期望行为 |
| --- | --- |
| 先看画布再动手 | 先调 `get_circuit` 拿到 `canvas` 尺寸和现有图元 |
| 坐标自行规划 | 不再是我给的固定坐标，且落在画布范围内 |
| 方向正确 | 用 `SourcePin`（方）当源，不是 `SinkPin`（圆） |
| 顺序合理 | 放元件 → 连线 → 设电平；或先设电平再连线都行 |
| 会复述结论 | 说出输出电平（High AND Low = `Low`） |

**典型失败**：坐标超界（会收到明确报错并自动重试，属于可接受的自愈）、
把 `SinkPin` 当源（会被工具拒绝）。

## 2. L2：只给功能目标

```text
我想验证一下：与门在两个输入都是高电平时，输出是不是高电平。
帮我把这个电路搭出来，然后告诉我结论。
```

**考察**：

- 自己推断需要哪些元件：1 个与门 + 2 个源 + 1 个接收端；
- 自己决定数量和位置，没人告诉它要几个；
- **验证**完要给结论，不是搭完就停；
- 两个输入都要设成 High（而不是只设一个）。

**判定**：结束时画布上应该有 4 个元件、3 条线，且它明确回答「输出是高电平」。

## 3. L3：现象驱动（排查）

先手动搭一个**半成品**：一个与门 + 两个输出引脚，但**只连一根线**。

然后：

```text
这个电路好像不太对，输出一直是 Off，帮我看看哪儿有问题。
```

**考察**：

- 先读画布，不臆断；
- 通过 `connections` / `nets` 发现少了一根线（而不是靠坐标瞎猜）；
- 补上缺的线后重新验证；
- 说清楚「原来哪里没连、现在补上了」。

**判定**：修复后输出不再是 `Off`。这条最接近真实使用——用户描述现象，Agent 自己定位。

## 4. L4：开放设计（难度高）

```text
帮我搭一个半加器：输入是两个一位二进制数，输出"和"和"进位"。用逻辑门实现就行。
```

**考察**：

- 知道半加器 = 一个 XOR（和）+ 一个 AND（进位）；
- 需要多级布局：2 个源 → XOR/AND → 2 个接收端；
- 坐标不能重叠（画布本来就窄，可能放不下）；
- 全部连线正确，两个输出都能读到值。

**这条大概率会遇到「画布放不下」**，此时期望的行为是：**如实说明空间不够、建议怎么调整**，
而不是硬塞或者假装完成。能诚实报告限制，也算通过。

## 5. 通用观察项

不管跑哪条，都看这几件事：

| 观察点 | 看哪里 |
| --- | --- |
| `get_circuit` 调用次数 | 网关日志；L1/L2 应在 2~3 次，不该每步都调 |
| 工具调用顺序是否合理 | 网关日志里 `tools/call` 的先后 |
| 有没有「先说明再改」 | 改画布前应有一句「我准备做 X」 |
| 失败后会不会调整 | 坐标超界后应换坐标重试，而不是重复同一次调用 |
| 有没有编造 | 工具返回 `verified.ok=false` 时不能宣称成功 |

## 6. 已知能力边界

当前工具集只有 `get_circuit` / `add_component` / `connect_pins` / `set_output_pin`：

- ❌ **不能删除元件**——所以「把与门换成或门」「清掉这些」这类目标必然失败；
- ❌ **不能移动已放置的元件**——位置错了只能撤销重来；
- ❌ 不能批量改多个引脚（一次一个）。

设计测试目标时避开这几种，或者专门用它们验证「Agent 遇到做不到的事会不会如实说」，
那是另一项有价值的观察。

## 7. 建议顺序

```text
L1（能自主搭一个门电路）
  ↓ 通过后再跑
L2（自己推断需要什么元件）
  ↓
L3（从现象定位问题，最像真实用法）
  ↓
L4（多级设计，可能会撞到画布限制）
```

每条跑完记录：用了多少次工具调用、`get_circuit` 几次、有没有失败重试、最终画布是否符合预期。
