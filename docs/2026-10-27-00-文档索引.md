# 文档索引与写作约定

> 读者：项目维护者 / Agent

## 1. 目录结构

```text
docs/
├── agent/   面向 Agent 的文档（默认）
├── user/    面向人的文档（仅明确说明时）
└── 2026-10-27-00-文档索引.md
```

默认新增文档放 `docs/agent/`；只有明确“面向用户/程序员”时，才放 `docs/user/`。

## 2. 两类文档

### 面向 Agent 的文档

给 Agent 做规划、写代码、改代码时读。

- 可以长，但必须结构化；
- 写清接口、数据结构、状态、边界和代码入口；
- 变更实现时同步更新，避免文档和代码脱节。

### 面向人的文档

给程序员快速理解、接入或排障时读。

- 尽量短，先给结论和最小示例；
- 建议控制在 150 行以内；
- 超过 150 行时拆成“快速开始 + 详细参考”；
- 表达用短句、步骤和表格，避免大段铺陈。

## 3. 日期与命名

- 文件名格式：`yyyy-mm-dd-hh-<name>.md`；
- 面向人的文档用中文名，例如 `2026-10-27-00-客户端快速接入.md`；
- 面向 Agent 的文档用英文 kebab-case，例如 `2026-10-27-00-streaming-design.md`；
- 新增文档必须登记到本文档清单。

## 5. 维护规则

- 面向 Agent 的文档可以长，但每个关键设计要有“当前状态”和“代码入口”；
- 面向人的文档只留“为什么这样设计”和“怎么用”，细节链接到 Agent 文档；
- 外部客户端接入先看 [客户端快速接入](./user/2026-10-27-00-客户端快速接入.md)，需要完整协议再看 [客户端接入指南](./user/2026-10-27-00-客户端接入指南.md)；
- 历史文档保留，但标题下要标注“历史说明”和当前替代文档；
- 新增文档时，按日期前缀命名并登记到本文档清单。
